## 2026-08-30｜VCL06 确定性任务核心

- 日期：2026-08-30
- 分支：`feat/vcl06-mission-core`
- 改动范围：`uav_mission` profile 加载、候选队列、任务 reducer、确定性测试和设计说明。
- 具体改动：
  - 新增无 ROS `CompetitionProfile` 加载器，未知 profile、空类别、非法权重和非法 top-k
    启动失败；正式 `r2026` 的中断集合固定为 `red_cross、panzer、bridge`。
  - 新增严格候选准入、稳定实例键、按类别去重的持久优先队列、顺序三槽、重试冷却及
    已投类别去重。
  - 新增仅限 SEARCH 的高权重中断、覆盖结束/动态时限低权重兜底、510 s 硬返航和
    三次提交即返航策略。
  - 新增结果身份核对、executor/event sequence 幂等 reducer，以及
    `release_ack_success` 后槽位不可回滚和恢复失败返航语义。
  - 补齐全局 decision sequence、冻结派发快照、targetless motion result、目标/搜索/返航/
    降落 deadline 和返航失败 ABORT；`APPROACH` 明确为带阶段回报的复合投递事务。
  - 新增 `CoverageRoute`：中断不推进、恢复原 nominal waypoint、匹配成功才推进、重复/
    错序结果无副作用，连续失败按上限显式跳过。
  - 将比赛配置、profile 权重和派发快照冻结；目标事务未见提交 ACK 就超时时隔离载荷槽位、
    禁止重试并返航，延迟且身份匹配的释放 ACK 仍可收敛为已提交，避免误复用已释放载荷。
  - decision 使用排他边界的有限执行租约，result 使用显式事件时间；超期释放 ACK 的归约
    同时受事件时间与 manager 接收时间约束，不依赖 timer/result 回调顺序；隔离事务保留
    release tombstone，510 s、600 s、4 m 硬边界均在构造和运行期 fail-closed。
  - 增加释放阶段安全锁存：未提交失败仅在 RELEASE 前释放槽位；一旦观察到 RELEASE/
    RECOVERY，后续阶段回退也不能解除隔离，迟到 guarded ACK 可把 tombstone 收敛为已提交。
- 验证结果：
  - `PYTHONPATH=src /usr/bin/python3 -m unittest discover -s test
    -p 'test_*.py' -v`：56/56 PASS。
  - `catkin_make -DROS_EDITION=ROS1 -DCATKIN_WHITELIST_PACKAGES=uav_mission -j1`：PASS。
  - `catkin_make ... run_tests_uav_mission -j1` 与 `catkin_test_results --verbose`：
    56 tests，0 errors，0 failures，0 skipped。
  - 未启动 ROS master、Gazebo、PX4、舵机或实机动作。
- 遗留问题：纯核心尚未消费 ROS 消息；planner status 和 decision/result
  运行话题仍需独立 manager 桥接，统一仿真实跑仍待视觉进程释放资源后排队执行。
- 下一步：新增只发布 `/navigation/mission_command_raw` 的 ROS manager，消费候选和
  `/navigation/mission_result`；正式模式不直接争用 `/fastplanner/goal`。
