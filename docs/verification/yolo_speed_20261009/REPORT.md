相机使用1280×720 MJPG，临时关闭自动曝光及允许曝光降帧的开关，现场接收约29 FPS。相机设置在四轮对照结束后已恢复。每轮采样30秒，不额外预热；按原版、优化版、原版、优化版顺序测试。

|---|---:|---:|---:|

两轮平均检测帧率从13.19提高到19.67 FPS，约提升49%。推理接口平均耗时从55.56降至40.46 ms，降低约27%。优化版Core0瞬时负载约64%，Core1和Core2为0%。这里是独立YOLO链的短时实测，不代表包含飞控、定位、规划和投递的完整飞行链路。

## 具体改动

1. 检测进程按CPU capacity识别并优先使用当前允许的大核；本板为CPU4–7。仅影响检测进程，不改变相机或导航进程的亲和性，不猜测其他板卡的CPU编号。
2. 查询实际模型输入属性，只有无额外填充的NHWC FP16模型输入且形状匹配时，才通过OpenCV SIMD把已经按原流程归一化的FP32数组转换为IEEE FP16并直接提交。保留RGB顺序、640尺寸及原归一化。避免RKNN输入端再次转换。不匹配的模型继续采用原提交路径。
3. 独立工作线程串行执行推理，待处理队列最多保留一张最新图像。订阅回调不再等待推理，减少ROS收图和推理之间的空档。保留阶段epoch检查，丢弃模式切换前的待处理帧；线程异常导致节点显式关闭。
4. OpenCV线程数设为1，避免检测进程无必要地扩展线程。

新增配置开关：native_fp16_input、prefer_big_cpus、latest_image_worker，均为true；opencv_threads为1。可分别关闭以进行对照。回到原执行策略需将前三项设为false，并将opencv_threads设为-1（不主动设置）或原板上的8。
