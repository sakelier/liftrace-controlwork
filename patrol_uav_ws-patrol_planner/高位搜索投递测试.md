```bash

source vision_ws/devel/setup.bash

```

## 二、启动顺序

### 1. 启动 MAVROS/PX4

```bash
roslaunch mavros px4.launch
```

确认飞控连接、位姿和里程计正常后再继续。

### 2. 启动 MID360

```bash
roslaunch livox_ros_driver2 msg_MID360.launch
```

应确认激光消息类型与工程现有 FAST-LIO 配置一致。

### 3. 启动相机

#### 方式一：向下相机（实机推荐，有标定）

使用已标定的 1280×720 向下相机，标定文件位于 `camera_sdk/param/calibration_1280x720.yaml`：

```bash
roslaunch camera_sdk camera_calibrated_1280x720.launch
```

该 launch 自动做了：

- 扫描 `/dev/video0,/dev/video1,/dev/video2` 找到可用设备
- 分辨率 1280×720、MJPG 编码、30Hz 发布
- 发布话题 `/camera/image_raw`、`/camera/camera_info`、`/camera/image_raw/compressed`
- TF frame\_id = `downward_camera_optical_frame`（与本 launch `camera_optical_frame` 参数默认值一致）

如果视频设备名不同（例如只有 `/dev/video0`），启动时覆盖：


### 启动舵机:
sudo bash patrol\_uav\_ws-patrol\_planner/src/actuator\_pwm/init\_pwm.sh

## 三、如何修改航线

### 3.1 手动打点（推荐）

编辑 `minimal_delivery_test.yaml` 的 `manual_waypoints` 段：

```yaml
navigation:
  mission_manager:
    search:
      manual_waypoints:
        - [-2.0, 0.0, 0.3]    # [x, y, z]  格式：camera_init 坐标系，单位米
        - [0.0,  0.0, 0.3]
        - [2.0,  0.0, 0.3]
        - [4.0,  0.0, 0.3]
        - [6.0,  0.0, 0.3]
        - [8.0,  0.0, 0.3]
      route_revision: minimal-delivery-test-manual-r1
```

每个航点格式为 `[x, y, z]`，其中：

- `x` 正方向为无人机初始机头朝向（camera\_init +X）
- `y` 正方向为机体左侧（camera\_init +Y）
- `z` 是 camera\_init 局部高度（相对建图原点）

例如改成 S 形航线：

```yaml
manual_waypoints:
  - [0.0,  0.0, 0.3]
  - [2.0,  1.0, 0.3]
  - [4.0, -1.0, 0.3]
  - [6.0,  1.0, 0.3]
  - [8.0,  0.0, 0.3]
```

### 3.2 自动之字形（可选）

如果删掉 `manual_waypoints` 整段，launch 会改用 `min_x / max_x / min_y / max_y / lane_spacing / altitude` 自动生成之字形航线：

```yaml
navigation:
  mission_manager:
    search:
      min_x: -2.0
      max_x: 8.0
      min_y: -1.0
      max_y: 1.0
      lane_spacing: 1.0
      altitude: 0.3
      route_revision: minimal-delivery-test-autozigzag-r1
```

### 3.3 航线修改规则

1. 航点必须是 `camera_init` 坐标系下的米制坐标。
2. 高度 `z` 是 FAST-LIO 局部估计高度，不一定等于离地高度。实机地面高度变化时，应先确认 LIO 原点和地面高度。
3. 航点之间由 Fast-Planner 根据实时点云重规划，航点只是阶段目标，不是强制直线飞行轨迹。
4. 修改后必须重新 `roslaunch`；运行中的任务不会自动读取文件变化。
5. 所有航点 z 应等于 `delivery/search_altitude`；不一致会导致飞行高度突变。

## 四、修改高度时还要同步修改

高度是多个子系统共享的参数，分散在 yaml 的不同 section 里。改高度时**必须同步所有副本**，否则实机会因参数约束校验失败而拒投：

| 参数位置                                | 当前值  | 约束         | 含义                   |
| ----------------------------------- | ---- | ---------- | -------------------- |
| `delivery/search_altitude`          | 0.3  | —          | 搜索航线高度（信息性记录）        |
| `delivery/approach_altitude`        | 0.3  | = search   | 逼近目标上方高度             |
| `delivery/return_altitude`          | 0.3  | —          | 返航飞行高度               |
| `waypoints[0].z`                    | 0.3  | = search   | patrol\_control 起飞高度 |
| `manual_waypoints[*][2]`            | 0.3  | = search   | 各搜索航点高度              |
| `mission/approach_altitude`         | 0.3  | = search   | MissionManager 传入规划器 |
| `mission/return_altitude`           | 0.3  | —          | MissionManager 返航高度  |
| `land_height`                       | 0.05 | < capture  | 控制器降落高度              |
| `align_height`                      | 0.3  | ≥ recovery | 视觉对准高度               |
| `external_landing/capture_height`   | 0.3  | = return   | 返航完成后自动降落交接高度       |
| `external_landing/auto_land_height` | 0.15 | ≥ land     | 视觉降落链关闭时仅作参数校验     |
| `uav_vision/recovery_height`        | 0.3  | ≤ align    | 投放后恢复高度              |
| `external_planner_max_command_z`    | 2.0  | 安全上限       | Fast-Planner 输出高度限制  |
